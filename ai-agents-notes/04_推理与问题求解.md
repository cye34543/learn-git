# 第4章：推理与问题求解

> 让 LLM 做数学题 — 它行吗？不配工具的话，挺容易翻车的。

---

## 什么是推理 Agent？

**推理 Agent** = 通过精心设计的系统提示词，让 LLM 进行逻辑分析、数学计算和多步骤问题求解。

### 打个比方
```
普通聊天模式                   推理模式
───────────────              ─────────────
"帮我算一下"                 "我是数学家，
"好的！答案是..."           我要仔细分析，
                          一步步计算..."
```

---

## 为什么推理对 LLM 很难？

LLM 训练时学的是"预测下一个词"，而不是"真正的逻辑推理"：

```
LLM 擅长：                    LLM 不擅长：
✓ 模式识别                    ✗ 多位数算术
✓ 模板套用                    ✗ 追踪多个变量
✓ 统计推断                    ✗ 系统性问题分解
✓ 见过的题目类型               ✗ 完全陌生的逻辑
```

---

## 例子中的复杂问题

教程用了一个很绕的人名关系题来测试：

> "我的家庭聚会需要做土豆泥。参加者包括我已婚的父母、我的双胞胎兄弟和他家人、我的姑姑和她家人、我奶奶和她兄弟......每个人能吃多少、多少人、怎么换算成几袋土豆？"

这个题目需要：
- 追踪15+个人物
- 理解家庭关系（婚姻、去世、饮食限制）
- 多步算术（人数×份量→总重量→袋数，向上取整）

---

## LLM 推理的常见失败

| 失败类型 | 例子 |
|---------|------|
| 计数错误 | 15个人可能数成14或16 |
| 算术错误 | 中间某步算错了 |
| 丢失信息 | 忘了"某些人不吃碳水" |

---

## 从弱到强的演进路线

```
第1级: 纯提示词(本章)
  用户 → LLM → 答案
  问题：所有计算都在"脑子里"，容易错

第2级: 思维链(Chain-of-Thought)
  用户 → LLM → 展示过程 → 答案
  改善：可以看到推理步骤

第3级: 工具辅助(第7章 simple-agent)
  用户 → LLM ⇄ 计算器 → 答案
  改善：计算交给外部工具，减少错误

第4级: ReAct模式(第9章)
  用户 → LLM → 思考→行动→观察→思考...
  最佳：明确的推理循环，每步都用工具验证
```

---

## 一句话总结

纯靠 LLM 做推理就像让人心算复杂的数学题 — 能做，但容易出错。解决方案是给它配工具（计算器等），这将在后续章节展开。
