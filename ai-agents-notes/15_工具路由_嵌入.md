# 第15章：工具路由 (嵌入向量匹配)

> 当一个 Agent 有几十上百个工具时，不能全塞进提示词。学会用"嵌入向量"做预筛选，只把最相关的几个工具发给 LLM。

---

## 问题：工具太多怎么办？

```
12个工具 → 12个定义塞进提示词（还行）
80个工具 → 80个定义（又吵又贵）
500个工具 → 完全不现实

解决思路：先筛选！
500个工具 → 预筛选出最相关的4个 → 只把这4个发给 LLM
```

---

## 工作流程

```
用户消息
  ↓
用小模型把消息转成向量（嵌入）
  ↓
和每个工具的"示例短语向量"计算余弦相似度
  ↓
每个工具得到一个相似度分数
  ↓
取分数最高的 top-k 个工具（加上固定工具）
  ↓
只把这些工具发给 LLM 做函数调用
```

---

## 工具路由的核心概念

### 1. 示例短语 (Exemplars)
为每个工具准备3条典型的用户问法：

```javascript
// VPN 工具的示例
"AnyConnect auth keeps timing out when working remotely"
"VPN client shows disconnected even after entering valid credentials"
"remote tunnel to corporate network not establishing from outside office"

// 账户工具的示例
"account suspended or locked in Active Directory after failed logins"
"verify user permissions and group membership in the directory"
```

**注意**：示例短语不应该和真实的用户查询一模一样，否则你测试的是字面匹配而不是语义匹配。

### 2. 余弦相似度
计算"用户消息"和每个"示例短语"在向量空间中的夹角，夹角越小 = 越相关。

### 3. 分数策略：取最大值
一个工具有多个示例，取**相似度最高的那个**作为工具的得分（不是平均值）。

### 4. 固定工具 (Always-include)
有些工具无论分数高低都必须始终可用：
- 合规工具（每次交互都要提供）
- 安全工具（某些话题必须出现）
- 上下文工具（每轮都需要，如获取用户信息）

---

## 可能的失败模式

| 失败模式 | 说明 | 缓解措施 |
|---------|------|---------|
| 召回失败 | 正确的工具没进 top-k | 更多示例、增大 k |
| 示例缺口 | 用户用词和所有示例都不一样 | 收集更多变形问法 |
| 多意图 + k太小 | 一句话需要2个工具但k=1只给1个 | 增大 k 或用固定工具 |
| 误判 | 无关工具因措辞模糊得到高分 | 增加精确的示例、混合关键词规则 |

教程的案例5故意展示了k=1时的召回失败；案例6展示了如何用固定工具解决。

---

## 一句话总结

工具路由 = 用嵌入向量做"为工具准备的 RAG 检索"。预计算所有工具的示例向量 → 用户消息一来就计算相似度 → 只把最相关的工具发给 LLM。工具多了也不怕，这就是规模化 Agent 的关键技术。
