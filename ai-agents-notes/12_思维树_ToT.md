# 第12章：思维树 (Tree of Thought / ToT)

> 同时探索多个思路，打分，剪枝，只保留最好的那个往下走。

---

## 核心思想

普通 LLM 是直线思考。ToT 是**分支探索**：

```
普通推理:  A → B → C → 答案（一条路走到黑）
ToT推理:  
          问题
        /  |  \
     分支1 分支2 分支3   （同时探索多条路）
       |    |    |
     评分  评分  评分
       |    |    |
      剪掉  保留  剪掉    （只留最好的）
            |
          答案
```

---

## 实际例子（心理学分析）

教程中分析了一个人的行为："某人辞掉稳定工作却没有明确规划"

**Phase 1 — 分支：**产生4种竞争性假设
- 回避型解释
- 倦怠型解释
- 成长型解释
- 外部压力解释

**Phase 2 — 评分：**每个假设从解释力、合理性、可证伪性打分

**Phase 3 — 剪枝：**只保留最高分（倦怠型得9分），其他丢弃

**Phase 4 — 结论：**仅基于胜出假设产生最终分析

结尾特意打印了**被丢弃的分支**，展示 ToT 的局限性——有用的信息可能在剪枝中丢失。

---

## 三个核心原则（代码实现）

| 原则 | 代码做的事 |
|------|-----------|
| 分支 | `developHypothesis()` 为每个视角生成一条假设 |
| 评分 | `scoreHypothesis()` 对每条假设独立打分 |
| 剪枝 | `pruneHypotheses()` 丢掉所有非赢家 |

---

## 什么时候用 ToT？

✅ **适合的场景：**

**运维场景**：API 延迟飙升
- 分支：数据库饱和、缓存失效、网络问题
- 评分：用仪表板和日志验证每个假设
- 剪枝：选最可能的根因
- 行动：执行一条修复路径

**开发场景**：优化慢接口
- 分支：加 Redis 缓存、重写 SQL 索引、预计算
- 评分：评估实现成本、风险、收益
- 剪枝：选一个策略实施

**Agent 构建场景**：AI 编程助手选修复策略
- 分支：最小补丁、深度重构、回滚+护栏
- 评分：失败风险、影响范围
- 剪枝：保持一条执行路径

---

## ToT 的局限性

教程特意展示了：**剪枝意味着信息丢失**。被丢弃的假设可能包含纠正性的洞察，但不会再影响最终结论。这就是严格 ToT 剪枝的核心局限。

---

## 一句话总结

ToT 让你同时探索多条路，打分挑最好的。适合需要快速决策、清晰赢家的场景。但记住：剪掉的也是信息，关键信息丢了就找不回来了。下一章 GoT 会解决这个问题。
