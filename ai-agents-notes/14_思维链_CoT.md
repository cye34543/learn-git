# 第14章：思维链 (Chain of Thought / CoT)

> 不让模型直接跳到结论，而是逼它一步步写出推理过程，像客服在做案件记录一样。

---

## 为什么要分步推理？

直接判断 vs 分步判断的区别：

```
直接判断:
"用户申请退货，耳机有间歇性声音丢失，买后23天，189欧元"
→ LLM: "批准" 或 "拒绝" （不知道为什么，可能随机）

分步判断 (CoT):
Phase 1: 事实提取（只看数据，不做判断）
Phase 2: 红旗筛查（列出欺诈风险点）
Phase 3: 合法性评估（列出顾客合理理由）
Phase 4: 政策检查（应用硬性规则）
Phase 5: 最终决策（综合所有信息）
→ 有理有据的结论，每一步都可审计
```

---

## 五个阶段及其作用

| 阶段 | 为什么存在 |
|------|-----------|
| **事实提取** | 防止过早偏见，先把已知信息和评估分开 |
| **红旗筛查** | 强制覆盖欺诈风险检查清单 |
| **合法性评估** | 保留顾客公平性，避免单方面怀疑 |
| **政策检查** | 用业务规则约束模型行为 |
| **决策** | 产生可追溯的结果和清晰的理由 |

---

## 关键价值：可审计、可纠正

```
欺诈分: 6/10
合法性分: 7/10

没有CoT: 直接分类器可能根据提示词措辞随机翻转
有了CoT: 可以检查每一步，定位弱环节（比如"合法性推理太弱"），只修那个阶段
```

---

## 什么时候用 CoT？

✅ **高影响力决策场景：**

- **客服退款判断**：需要透明理由，方便审核
- **运维部署审批**：高风险操作需要可审计的决策链
- **代码审查**：争议性 PR 需要结构化的风险评估
- **合规审核**：每一步都要能回溯

---

## 一句话总结

CoT 不只是让答案更准，它让决策过程变得**可治理**。主管可以审计为什么通过/拒绝，团队可以发现推理在哪个环节出了问题。对于有合规要求的生产级 Agent 来说，CoT 是必备的。
