# 第1章：基础 LLM 交互

> 从最基础的开始 — 加载一个本地模型，问它一个问题。

---

## 什么是本地 LLM？

**本地 LLM** 就是跑在你自己的电脑上的 AI 语言模型。不需要联网，不需要调用外部 API。

**好处：**
- **隐私**：数据不会离开你的电脑
- **免费**：没有按次收费
- **可控**：你可以完全控制模型和参数
- **离线**：断网也能用

---

## 核心组件

### 1. GGUF 模型文件
- `.gguf` 是一种为本地运行优化的模型文件格式
- **量化(Quantization)**：把模型"压缩"，比如从16位精度降到8位，文件变小但质量微降
- 模型文件存储在 `./models/` 目录下

### 2. 推理管线（怎么从问题得到答案）

```
用户输入 → 模型上下文 → 模型推理 → 生成回复
   "你好"       记忆空间      计算        "你好！"
```

### 3. 上下文窗口（Context Window）

**上下文**就是模型的"工作记忆"，有固定大小限制（比如4096个令牌）：

```
┌────────────────────────────────┐
│       上下文窗口              │
│  系统提示词 (如果有)          │
│  用户: "你知道node-llama吗？" │
│  AI: "是的，这是..."          │
│  (留给后续对话的空间)         │
└────────────────────────────────┘
```

---

## LLM 怎么生成回复？

LLM 不是一个字一个字说出来的，而是一个**令牌(token)**一个令牌生成的：

```
输入: "什么是AI？"

生成过程:
"什么是AI？" → [模型] → "AI"
"什么是AI？AI" → [模型] → "是"
"什么是AI？AI是" → [模型] → "一个"
...持续到满足停止条件
```

> 一个令牌大约等于 0.75 个英文单词。中文一个字通常是一个令牌。

---

## 对 Agent 的关键启示

1. **LLM 是无状态的**：每次问答都是独立的，除非你自己维护上下文
2. **提示词写法很重要**：问法不同，答案质量天差地别
3. **Agent 需要的基础**：
   - 维持对话上下文
   - 保存对话历史
   - 添加工具/函数（后面章节会讲）

---

## 一句话总结

这章就是教你：下载模型文件 → 加载到内存 → 发送问题 → 得到回答。这是所有 Agent 的地基。
