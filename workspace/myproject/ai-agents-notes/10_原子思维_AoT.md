# 第10章：原子思维 (AoT)

> "推理界的 SQL" — 把复杂任务拆成最小的、不可再分的步骤。

---

## 什么是原子思维？

**AoT = Atom of Thought**

就像 SQL 把复杂数据操作拆成一个个原子语句（SELECT、WHERE、JOIN），AoT 把推理拆成最小的、可独立验证的步骤。

### 示例对比

❌ **非原子**（复合语句）：
```
"搜索格拉茨的酒店，筛选能容纳30人以上的"
```

✅ **原子化**（分开的步骤）：
```
原子1: 搜索格拉茨的酒店
原子2: 筛选容纳人数≥30的
```

---

## 三层架构

```
┌─────────────────────────────┐
│  LLM（规划层）              │
│  - 只负责制定计划           │
│  - 不执行                   │
└──────────────┬──────────────┘
               ↓
┌─────────────────────────────┐
│  验证器（安全层）            │
│  - 检查计划结构             │
│  - 验证依赖关系             │
└──────────────┬──────────────┘
               ↓
┌─────────────────────────────┐
│  执行器（执行层）            │
│  - 按顺序执行原子步骤       │
│  - 管理状态                 │
└─────────────────────────────┘
```

**关键思想**：LLM 只管规划，执行交给确定的代码。不再让 LLM 边想边做（容易出错）。

---

## 原子的结构

```json
{
  "id": 2,
  "kind": "tool",
  "name": "multiply",
  "input": {
    "a": "<result_of_1>",   // 引用前面原子的结果
    "b": 3
  },
  "dependsOn": [1]          // 必须等原子1完成
}
```

---

## AoT vs ReAct

| 方面 | ReAct | AoT |
|------|-------|-----|
| 输出格式 | 自然语言 | 结构化 JSON |
| 能否在执行前验证 | 不能 | 可以 |
| 能否独立测试执行器 | 要模拟整个 LLM | 直接测执行器代码 |
| 调试难度 | 要通读整个对话文本 | 定位到具体某个原子 |
| 能否重放 | 重跑整个对话 | 从任意原子重新开始 |

### 同一个问题，两种输出：

**ReAct**: 10行自然语言推理

**AoT**: 一个 JSON 计划，每个步骤都是结构化的、可验证的。

## 依赖图（DAG）

```
     ┌─────┐
     │  1  │ add(15, 7)
     └──┬──┘
        │
     ┌──▼──┐
     │  2  │ multiply(result_1, 3)
     └──┬──┘
        │
     ┌──▼──┐
     │  3  │ subtract(result_2, 10)
     └──┬──┘
        │
     ┌──▼──┐
     │  4  │ final
     └─────┘
```

- 可按拓扑序执行
- 独立的原子可以并行
- 失败就停在那一步，不会污染后面
- 一目了然的依赖关系

---

## 什么时候用 AoT？

✅ **适合：**
- 多步骤工作流（预订、审批流程）
- API 编排（调用A，用A的结果调B）
- 金融交易（可审计、可回滚）
- 合规系统（每一步都有日志）

❌ **不适合：**
- 创意写作
- 开放式探索
- 头脑风暴
- 单步简单问答

---

## 一句话总结

AoT 的思路是"先规划，后执行"。LLM 输出一个 JSON 格式的计划，然后由确定性代码一步步执行。好处是每一步都可验证、可调试、可重放。适合对可靠性要求高的生产环境。
