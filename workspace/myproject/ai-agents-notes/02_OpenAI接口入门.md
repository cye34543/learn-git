# 第2章：OpenAI 接口入门

> 不跑本地模型，改用 OpenAI 的云端 API。更快、更强，但要花钱。

---

## OpenAI API vs 本地 LLM

| 方面 | OpenAI API | 本地 LLM |
|------|-----------|---------|
| 设置 | 只需 API Key | 要下载模型，需要 GPU/RAM |
| 费用 | 按令牌计费 | 初始设置后免费 |
| 性能 | 稳定、高质量 | 取决于你的硬件 |
| 隐私 | 数据发送到云端 | 完全本地/私密 |
| 扩展性 | 无限(付费) | 受硬件限制 |

## 消息角色（Message Roles）

每次和 LLM 对话，消息有三种角色：

### 1. System（系统消息）
```javascript
{ role: 'system', content: '你是一个Python教学助手。' }
```
**作用**：定义 AI 的行为、性格、能力边界。用户看不见，但它影响每一次回复。
> 类比：这就是给 AI 发的"岗位说明书"。

### 2. User（用户消息）
```javascript
{ role: 'user', content: '怎么用 async/await？' }
```
**作用**：你的问题或指令。

### 3. Assistant（助手消息）
```javascript
{ role: 'assistant', content: 'async/await 是处理异步操作...' }
```
**作用**：AI 之前的回复，用来维护对话历史。

## 核心概念

### 温度 (Temperature)
控制回复的"创造性"：

| 温度值 | 效果 | 适用场景 |
|--------|------|---------|
| 0.0-0.3 | 确定性强，每次回答类似 | 代码生成、事实问答 |
| 0.5-0.9 | 平衡创造性和连贯性 | 客服、内容总结 |
| 1.0-2.0 | 非常有创意，结果多样化 | 写故事、头脑风暴 |

### 流式输出 (Streaming)
不用等完整回复，一个字一个字地看 AI 生成：
```
普通模式:  [等10秒...] 完整回复一次出现
流式模式:  "流"→"式"→"输"→"出"→... 即时显示
```

### 令牌 (Token) — LLM 的“货币”
- 你按令牌付费（输入+输出都算）
- 不同模型有令牌上限（如 GPT-4o: 128K 令牌）
- 1 令牌 ≈ 0.75 个英文单词

## 重要原则：API 是无状态的

每发一次请求，模型不记得之前的对话。你自己必须在每次请求里带上完整的历史记录。

```javascript
// 你需要自己维护消息历史
const messages = [];  
messages.push({ role: 'user', content: '我叫小明' });
// 下次请求必须带着整个 messages 数组
```
