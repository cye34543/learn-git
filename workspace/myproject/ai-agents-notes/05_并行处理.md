# 第5章：并行处理与性能优化

> 同时处理多个请求，而不是一个接一个排队。效率翻倍的关键技术。

---

## 顺序 vs 并行

```
顺序处理（慢）:
请求1 ────→ 回复1 (2秒)
                ↓
          请求2 ────→ 回复2 (2秒)
                          ↓
                    总时间: 4秒

并行处理（快）:
请求1 ────→ 回复1 (2秒) ──┐
                          ├→ 总时间: 2秒
请求2 ────→ 回复2 (2秒) ──┘
(两个请求同时运行)
```

**2倍加速！**

---

## 核心概念：上下文序列 (Context Sequence)

一个模型可以同时维护多个独立的"对话序列"：

```
┌──────────────────────────────────┐
│         模型（只加载一次）         │
├──────────────────────────────────┤
│  序列1: 对话历史A                 │
│  序列2: 对话历史B                 │
│  序列3: 对话历史C                 │
└──────────────────────────────────┘
```

关键：**模型权重共享**（省内存），但每个序列有**独立的历史记录**。

---

## JavaScript 的 Promise.all

```javascript
// 顺序（慢）
const r1 = await session1.prompt(q1);  // 等2秒
const r2 = await session2.prompt(q2);  // 再等2秒

// 并行（快）
const [r1, r2] = await Promise.all([
    session1.prompt(q1),  // 同时开始
    session2.prompt(q2)   // 同时开始
]);
// 只需等2秒（取最慢的那个）
```

## 适用场景

| 场景 | 示例 |
|------|------|
| 多用户 | 同时处理用户A、B、C的请求 |
| 多Agent | 规划Agent和研究Agent同时工作 |
| 批量处理 | 一次分析1000份文档 |
| A/B测试 | 同时测试两套系统提示词 |

## 资源管理

每个序列都要吃显存。你的显卡能跑几个序列？

```
总显存 8GB
├─ 模型权重: 4GB
├─ 上下文: 1GB
├─ 序列1 KV缓存: 0.8GB
├─ 序列2 KV缓存: 0.8GB
├─ 序列3 KV缓存: 0.8GB
├─ 其他开销: 0.6GB
└─ 已满！
```

---

## 一句话总结

并行处理是生产级 Agent 系统的必备技能。多创建几个序列，用 `Promise.all` 同时工作，吞吐量能提升数倍。但别忘了你的显存是有限的。
